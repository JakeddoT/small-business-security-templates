Microsoft 365 security defaults vs Conditional Access: which should a small business use?

By William Todd, IT support and cybersecurity engineer · Updated 2026-11-22

If your Microsoft 365 plan doesn't include Microsoft Entra ID P1 (for example, Business Basic or Business Standard on their own), turn on security defaults: it's free and enforces MFA registration for everyone, requires MFA for admins, prompts users for MFA when needed, and blocks legacy authentication. If you have Entra ID P1, which is included in Microsoft 365 Business Premium, use Conditional Access instead, because it lets you set the same protections more precisely and add exceptions safely. You can't use both at once.

Before you switch anything on

  • Make sure you have two working admin accounts, each with MFA, so a mistake doesn't lock everyone out. Consider one break-glass emergency account stored securely, as Microsoft recommends for Conditional Access.
  • Find anything using legacy authentication: old copiers scanning to email, old mail apps, line-of-business tools. Blocking legacy auth will stop them (see the printer and copier checklist).
  • Tell staff they'll be asked to set up the Microsoft Authenticator app, and give them a date (see the MFA rollout plan).

Starter Conditional Access policies for a small business

If you have P1, these are commonly recommended starting points. Microsoft provides templates for many of them in the Entra admin center. Create them in report-only mode first, check the sign-in logs for anything they would block, then turn them on.

  1. Require MFA for all users, excluding only the break-glass account.
  2. Require MFA for admin roles, ideally with phishing-resistant methods.
  3. Block legacy authentication.
  4. Require MFA to register security information, so an attacker with a password can't add their own MFA method.
  5. Optional: block sign-ins from countries you never operate in, or require a compliant device for admin access, once the basics are stable.

Switching from security defaults to Conditional Access

  1. Build your Conditional Access policies in report-only mode.
  2. Check the sign-in logs for a few days.
  3. Turn off security defaults and turn the policies on in the same session, so there's no gap without MFA.
  4. Test signing in as a normal user and as an admin.

Check it's working

  • Look at the MFA registration report: every active user should be registered.
  • Look at sign-in logs for legacy authentication attempts and failures.
  • Check Microsoft Secure Score: MFA and legacy authentication items should show as complete.
  • Keep a screenshot of the settings for your insurance renewal evidence folder (see the insurer MFA requirements).

Licensing and admin center menus change; check Microsoft's current documentation for your plan before making changes. If an account has already been compromised, follow the Microsoft 365 hacked account checklist first.

Frequently asked questions

Should a small business use security defaults or Conditional Access?

Use security defaults if your plan doesn't include Microsoft Entra ID P1. If you have P1, for example through Microsoft 365 Business Premium, Conditional Access gives you more precise control. You can't use both at the same time.

What do Microsoft 365 security defaults do?

They require everyone to register for MFA, require MFA for administrators, prompt users for MFA when needed, and block legacy authentication protocols.

What Conditional Access policies should a small business start with?

Require MFA for all users, require MFA for admin roles, block legacy authentication, and require MFA to register security information, each tested in report-only mode first.
