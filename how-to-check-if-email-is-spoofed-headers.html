How to check if an email is spoofed: reading headers in Outlook and Gmail

By William Todd, IT support and cybersecurity engineer · Updated 2026-11-22

To check whether an email really came from who it says: look at the full sender address (not just the display name), check it for look-alike spellings, then open the message headers (in Gmail, the three-dot menu → Show original; in Outlook on the web, the three-dot menu → View → View message details; in Outlook desktop, File → Properties → Internet headers) and look for the SPF, DKIM and DMARC results. A "fail" on DMARC, or a pass for a domain that isn't the company's real domain, is a strong sign of spoofing or impersonation. When money or passwords are involved, verify by phone on a known number whatever the headers say.

Step 1: look past the display name

Email apps show a friendly name like "Jane Smith, CEO" and often hide the actual address. Hover over or tap the name to see the full address. Common tricks:

TrickExample
Right name, wrong address"Jane Smith" <jane.smith.ceo@gmail.com>
Look-alike domainexamp1e.com, example-co.com, example.co instead of example.com
Subdomain trickbilling@example.com.secure-pay.net (the real domain is secure-pay.net)
Reply-To mismatchFrom shows your supplier, but replies go to a different address

Check the Reply-To too: click Reply and see which address appears before you send anything.

Step 2: open the headers

AppWhere (menus can change)
Gmail (web)Open the email → three-dot menu → Show original
Outlook on the web / new OutlookOpen the email → three-dot menu → View → View message details
Outlook desktop (classic)Open the email in its own window → File → Properties → Internet headers
Apple MailView → Message → All Headers

Gmail's "Show original" page usefully summarizes SPF, DKIM and DMARC as PASS or FAIL at the top. Microsoft also offers a free Message Header Analyzer that turns pasted headers into a readable table.

Step 3: read the authentication results

Look for a line called Authentication-Results (Microsoft 365 also adds ARC-Authentication-Results and X-MS-Exchange-Organization-AuthAs). The parts that matter:

ResultMeaning
spf=passThe sending server is allowed to send for the domain shown in the envelope sender
dkim=pass header.d=example.comThe message was signed by example.com and wasn't altered
dmarc=pass header.from=example.comSPF or DKIM passed for the same domain that appears in the From address. This is the key one
dmarc=failThe From domain wasn't authenticated: likely spoofed
dmarc=none or bestguesspassThe domain has no enforced DMARC policy, so spoofing it is easier; be cautious

Important: a pass only proves the email came from the domain it was authenticated for. A scammer's own look-alike domain can pass everything. So always compare the authenticated domain with the company's real domain.

What the headers can't tell you

  • A real account that's been hacked. If a supplier's mailbox is compromised, their emails will pass every check. That's why bank detail changes always need a phone call (see bank detail change verification).
  • Intent. A legitimate marketing tool can send convincing phishing too.

If it looks spoofed

  1. Don't reply, click or open attachments.
  2. Report it using your email app's report phishing button, and tell IT.
  3. If it impersonates your own domain, check your SPF, DKIM and DMARC setup and consider moving DMARC to quarantine or reject (see SPF, DKIM and DMARC setup).
  4. If someone already acted on it, follow clicked a phishing link or, for payments, call the bank immediately.

Teach staff the first step (check the real address and Reply-To); the header check is for whoever handles IT. See the phishing red flags poster for the rest.

Frequently asked questions

How can I tell if an email is spoofed?

Check the full sender address and Reply-To for look-alike domains, then open the headers and look for SPF, DKIM and DMARC results. A DMARC fail, or a pass for a domain that isn't the real company's, suggests spoofing.

How do I see email headers in Outlook and Gmail?

In Gmail use the three-dot menu and Show original. In Outlook on the web use the three-dot menu, View, View message details. In classic Outlook open the message, then File, Properties, Internet headers.

If an email passes SPF, DKIM and DMARC, is it safe?

Not necessarily. It proves the email came from the authenticated domain, which could be a look-alike domain or a real but hacked account. Verify payment or password requests by phone.
