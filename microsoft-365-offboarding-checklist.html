Microsoft 365 offboarding checklist

By William Todd, IT support and cybersecurity engineer · Updated 2026-11-21

To offboard a Microsoft 365 user: block sign-in, reset the password, revoke their sessions, remove MFA methods and devices, and check mail forwarding and inbox rules, all on the last day. Then convert the mailbox to a shared mailbox, give the manager their OneDrive files, and remove the license. Disabling the account is only step one. Former employees often keep access through sessions that stay signed in, phones that still sync mail, forwarding rules, or third-party apps they connected.

This guide is written for small businesses with 5–100 users and an office manager or IT provider doing the work in the Microsoft 365 admin center. Admin center menus change from time to time, so treat the paths below as a guide and check Microsoft's own "remove a former employee" documentation if a menu has moved.

On the last day (in this order)

  1. Block sign-in in the Microsoft 365 admin center (Users → Active users → select user → Block sign-in). This stops new sign-ins.
  2. Reset the password to a long random value, even though sign-in is blocked. Don't tell anyone the new value; store it in your password manager if you'll need it.
  3. Revoke sessions. In the Entra admin center, open the user and choose Revoke sessions. This revokes their refresh tokens. Apps can keep working on an existing access token for up to about an hour, which is one more reason to do this early and check the sign-in logs afterwards.
  4. Remove their MFA methods and any registered devices so they can't be used for account recovery.
  5. Wipe or remove mobile devices. If you use Intune, retire company data from personal phones or wipe company-owned devices. If not, remove the mobile device partnership for the mailbox in Exchange.
  6. Check mailbox forwarding and inbox rules. Remove any forwarding to outside addresses and any rules that delete, move or redirect mail. Departing staff sometimes forward mail to a personal address "to keep contacts", and attackers use the same trick.
  7. Remove admin roles and group memberships, including distribution lists, Teams ownership and SharePoint site ownership.
  8. Collect company devices and change any shared passwords they knew (see below).

Quick PowerShell checks

If you or your IT provider use PowerShell, these read-only checks confirm the last-day steps worked. Run them from a connected Exchange Online and Microsoft Graph session, and check Microsoft's reference pages for the exact syntax in your module version.

CheckCommandWhat you want to see
Mailbox-level forwardingGet-Mailbox jane@contoso.com | fl ForwardingAddress,ForwardingSmtpAddress,DeliverToMailboxAndForwardBoth forwarding fields empty
Inbox rules, including hidden onesGet-InboxRule -Mailbox jane@contoso.com -IncludeHidden | fl Name,Enabled,RedirectTo,Forward*No rules forwarding or redirecting outside the company
Mobile devicesGet-MobileDevice -Mailbox jane@contoso.comNo devices still listed, or all wiped
Revoke sessionsRevoke-MgUserSignInSession -UserId jane@contoso.comReturns true

Handle the mailbox and files

  • Convert the mailbox to a shared mailbox if someone needs to keep reading it, and give the manager access. Shared mailboxes under 50 GB without an archive generally don't need a license.
  • Set an auto-reply that tells senders who to contact instead.
  • OneDrive files: by default, when you delete the user, their manager is automatically given access to their OneDrive, and the files are kept for 30 days unless your admin has changed the retention setting (it can be set from 30 to 3,650 days in the SharePoint admin center). That clock only starts when the account is deleted, not when sign-in is blocked or the license is removed. Move anything the business needs to a SharePoint site the team owns before then.
  • Legal or HR hold: if there's a dispute, a lawsuit risk or a retention requirement, place a litigation hold on the mailbox while the user is still licensed and confirm it's on before deleting the account. Deleting a mailbox that's on hold makes it an inactive mailbox that's kept. Litigation hold needs Exchange Online Plan 2 (included in Office 365 and Microsoft 365 E3/E5) or an Exchange Online Archiving add-on, so check your plan, and ask your lawyer if a hold is needed.

Within the first week

  • Remove the license once the mailbox is converted and the data is moved. On most plans this is where the cost saving happens.
  • Review sign-in logs for the account after the block date (Entra admin center → the user → Sign-in logs). Any successful sign-in after the block is a red flag worth investigating.
  • Rotate shared passwords they knew: admin accounts, banking, payroll, domain registrar, social media and vendor portals. This step is the one most often missed.
  • Review third-party apps they consented to with their account (Entra → Enterprise applications). Entra can't directly revoke tokens an outside app issued itself, so remove the app's access in that app too.
  • Update anything that ran under their account: scheduled flows, shared calendars, Forms, and service connections.

A log like this is what a cyber insurer or auditor wants to see when they ask how you remove access for leavers. It also catches the steps that slip when offboarding is rushed.

When the departure isn't friendly

For a termination, do the first three last-day steps (block, reset, revoke) during the meeting, not after. Ask for company devices in the same meeting. If you think they may already have taken data or set up forwarding, check the rules and the audit log first and keep notes, and talk to your lawyer before deleting anything.

Frequently asked questions

Does blocking sign-in log a user out of Microsoft 365 immediately?

Not always. Existing sessions can keep working until their tokens expire, so you should also revoke sessions in Entra ID.

Should I delete a former employee's Microsoft 365 account?

Usually not right away. Block sign-in, convert the mailbox to a shared mailbox if needed, and move files first. Then remove the license.

Do shared mailboxes need a license?

Shared mailboxes up to 50 GB without an archive generally do not need a license. Larger mailboxes or archiving need one.

How long is a deleted user's OneDrive kept in Microsoft 365?

By default 30 days after the account is deleted, and the user's manager is given access automatically. Admins can change the retention period from 30 to 3,650 days in the SharePoint admin center.

How do I check if a former employee is forwarding Microsoft 365 email?

Check the mailbox's forwarding settings and inbox rules in the Exchange admin center, or run Get-Mailbox to see ForwardingSmtpAddress and Get-InboxRule with -IncludeHidden in Exchange Online PowerShell.
