Windows security audit with PowerShell: what to check on every PC

By William Todd, IT support and cybersecurity engineer · Updated 2026-11-22

A quick Windows security audit checks about a dozen things on each PC: antivirus, firewall, disk encryption, patch age, local administrators, Remote Desktop, SMBv1, UAC, screen lock, the Guest account, pending reboots and listening ports. Every one can be checked with a read-only PowerShell command, so you can baseline a client's PCs in minutes before onboarding or after an incident.

Run these in an elevated PowerShell window (right-click Start → Terminal (Admin)). None of them change anything.

The checks, with commands

CheckCommand (read-only)Good result
Defender real-time protection and signature ageGet-MpComputerStatus | Select RealTimeProtectionEnabled, AntivirusSignatureAgeTrue; signatures 0–2 days old
Firewall profilesGet-NetFirewallProfile | Select Name, EnabledEnabled on Domain, Private and Public
BitLockerGet-BitLockerVolume -MountPoint C: | Select VolumeStatus, ProtectionStatusFullyEncrypted, On (how to read it)
Last installed updatesGet-HotFix | Sort-Object InstalledOn -Descending | Select -First 5Most recent within ~30 days
Local administratorsGet-LocalGroupMember AdministratorsOnly the expected IT/admin accounts, not everyday users
Remote Desktop enabled(Get-ItemProperty 'HKLM:\System\CurrentControlSet\Control\Terminal Server').fDenyTSConnections1 (disabled), or 0 only where RDP is needed and not internet-exposed (check exposure)
SMBv1Get-SmbServerConfiguration | Select EnableSMB1ProtocolFalse
UAC(Get-ItemProperty 'HKLM:\Software\Microsoft\Windows\CurrentVersion\Policies\System').EnableLUA1
Guest accountGet-LocalUser Guest | Select EnabledFalse
Pending rebootTest-Path 'HKLM:\Software\Microsoft\Windows\CurrentVersion\WindowsUpdate\Auto Update\RebootRequired'False (True means updates aren't fully applied)
Listening portsGet-NetTCPConnection -State Listen | Sort LocalPort | Select LocalAddress, LocalPort, OwningProcessOnly ports you can explain
PowerShell v2 (legacy engine)Get-WindowsOptionalFeature -Online -FeatureName MicrosoftWindowsPowerShellV2RootDisabled, or not present on newer builds

How to read the results

  • Fix FAILs first: antivirus off, firewall off, unencrypted laptops, SMBv1 on, everyday users in Administrators. These are the issues attackers and insurers care about most.
  • Then WARNs: updates more than 30 days old, RDP enabled, pending reboots, unexplained listening ports.
  • Record everything. Save the output per PC with the date. It's your baseline for the client, and evidence for an insurer or auditor that you checked.

Screen lock check

The intro lists screen lock, so here's one way to check it. If a machine inactivity limit is set by policy, it shows here (in seconds):

(Get-ItemProperty 'HKLM:\Software\Microsoft\Windows\CurrentVersion\Policies\System' -ErrorAction SilentlyContinue).InactivityTimeoutSecs

No value means no machine-wide limit is set by that policy. The screen may still lock through user settings, Intune or other policies, so confirm on the device if in doubt. Around 900 seconds (15 minutes) or less is a common target.

Checking several PCs at once

  • With PowerShell remoting enabled on a domain or managed network, you can run a check across PCs from one admin machine, for example:
    Invoke-Command -ComputerName PC1,PC2,PC3 -ScriptBlock { Get-MpComputerStatus } | Select PSComputerName, RealTimeProtectionEnabled, AntivirusSignatureAge
    Remoting isn't on by default for every setup, so don't open it up just for this.
  • With an RMM tool or Intune, run the same read-only commands as a script and collect the output centrally.
  • On a small office with no management tools, run the checks locally on each PC and save the output to a shared folder, named by PC and date.

What these checks don't cover

  • Cloud settings such as MFA and admin roles in Microsoft 365 or Google Workspace (see Microsoft Secure Score and the Google Workspace settings checklist).
  • Backups: a backup isn't proven until you restore from it (see the restore test).
  • Admin password hygiene: whether every PC shares one local admin password (see local admin rights and LAPS).
  • The network edge: router port forwards and firewall rules need checking on the router itself.

Frequently asked questions

How do I check if BitLocker is on with PowerShell?

Run Get-BitLockerVolume in an elevated PowerShell window and check ProtectionStatus.

How do I check if SMBv1 is enabled?

Run Get-SmbServerConfiguration | Select EnableSMB1Protocol in PowerShell.

How do I check Windows Defender status with PowerShell?

Run Get-MpComputerStatus in an elevated PowerShell window and check RealTimeProtectionEnabled (should be True) and AntivirusSignatureAge (should be 0 to 2 days).

How do I list local administrators with PowerShell?

Run Get-LocalGroupMember Administrators in an elevated PowerShell window. Everyday user accounts shouldn't be in the list.

Are these PowerShell audit commands safe to run?

Yes. The commands listed are read-only Get and Test commands that report settings without changing them. Run them in an elevated window for complete results.

How do I audit security on several Windows PCs at once?

Use PowerShell remoting with Invoke-Command where it's already enabled, run the checks as a script through your RMM or Intune, or run them locally on each PC and save the output by PC name and date.

How often should I run a Windows security audit?

When onboarding a PC or client, monthly or quarterly to catch drift, before cyber insurance renewal, after an incident and after major Windows upgrades.
