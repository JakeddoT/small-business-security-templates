New employee IT security onboarding checklist for small business

By William Todd, IT support and cybersecurity engineer · Updated 2026-11-21

Set up every new hire with their own named accounts, MFA from day one, only the access their job needs, a password manager, a secured device, a signed acceptable use policy, and a 15-minute security briefing. Getting this right on day one is far easier than fixing it later, and it makes the eventual offboarding clean.

Most access problems at small businesses start at onboarding: a shared login "just for now", admin rights because an app wouldn't install, a password sent by text. Use the checklist below for every new employee, contractor and temp.

Day one

  • Hand over credentials in person or by phone. Never send a password and username in the same email or text. Use a temporary password that must be changed at first sign-in.
  • Set up MFA together before they read a single email: install the authenticator app and register it, or issue a security key.
  • Set up the password manager and move any work passwords they'll use into it.
  • Sign the acceptable use policy and, if relevant, the BYOD policy before adding work email to a personal phone. See the acceptable use policy template.
  • Run a 15-minute security briefing (outline below) and record it in the training log.

The 15-minute day-one briefing

  1. Phishing: the red flags and what a fake sign-in page looks like. Give them the free red flags poster.
  2. MFA: never approve a prompt you didn't start; report it.
  3. Payments: any request to change bank details gets a callback to a known number (why).
  4. Where data goes: approved storage only, no personal email or USB drives.
  5. How to report: who to call, and that honest mistakes reported fast won't be punished.

First 30 days

  • Check the person has only the access they need. Remove anything granted "temporarily" during setup.
  • Confirm MFA is registered and enforced (look at the registration report, not just the policy).
  • Confirm their device appears in your management or antivirus console.
  • Ask the manager whether anything is missing, rather than letting the employee borrow a colleague's login.

Contractors and temps

  • Same rules: named accounts, MFA, least privilege. No shared "temp" login.
  • Set an account expiry date to match the contract end.
  • Add them to the offboarding calendar the day they start.

Common mistakes

  • Making new hires local admins so software installs go smoothly. Install it for them instead.
  • Copying another user's permissions ("make her like John"). John has years of extra access.
  • Skipping MFA "until they're settled". That's exactly when they're most likely to fall for a phishing email.

Frequently asked questions

What should be on an employee IT onboarding checklist?

Named accounts, MFA set up on day one, least-privilege access to apps and shared data, a password manager, a secured device where the user isn't a local admin, a signed acceptable use policy and a short security briefing.

Should new employees have admin rights on their computer?

No. Everyday accounts shouldn't be local administrators. Install required software for them, and give admin rights only to separate admin accounts used by IT.

How should I give a new employee their password?

In person or by phone, never in the same message as the username. Use a temporary password that must be changed at first sign-in, then set up MFA immediately.
